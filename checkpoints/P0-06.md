# P0-6 — Config schema: `tenantId` — DONE

`tenantId` is now a REQUIRED, shape-checked top-level key of the client config,
enforced by both validators, present in both real configs, and consumed by
nothing.

## What changed

| File | Change |
|---|---|
| `core_app/lib/app/config/client_config.dart` | `static final RegExp tenantIdPattern` + a required/shape check in `ClientConfig.fromMap` (the runtime boot gate) |
| `core_app/tool/whitelabel.dart` | Same check inside the generator's `validate()`; `tenantId` added to `knownTopLevelKeys` (a valid key must not trip the unknown-key guard); `ClientCoreConfig.tenantId` getter with the same fail-fast shape as `clientId` |
| `core_app/assets/client_config.json` | `"tenantId": "carnama"` |
| `apps/halal_boyz/assets/client_config.json` | `"tenantId": "halal_boyz"` |
| 5 test files | fixtures gained `tenantId`; 4 new runtime cases added |

Rules: non-empty string, lowercase kebab/snake (`^[a-z0-9]+([_-][a-z0-9]+)*$`).
A non-string is refused, never coerced. The two validators are intentionally
duplicated (the generator must not import app lib code) and the existing
identity test pins them together.

## Evidence

**Both validators reject a config without it** — real generation run, real exit
code, no artifacts:

```text
$ node -e '…delete j.tenantId…'                       # scratch copy
scratch written, tenantId present = false
$ dart run tool/whitelabel.dart --config ../apps/halal_boyz/assets/_tenant_probe_config.json --dry-run
ERROR: Invalid client config:
  - "tenantId" is required and must be a non-empty kebab/snake id (lowercase
    letters, digits, "-" or "_"), e.g. "halal_boyz".
SCRATCH_EXIT=65
scratch removed: yes
```

Refusal happens at validation, i.e. **before generation** — the card's
"without leaving generated client artifacts behind" clause holds because no
client directory was created; the scratch file was deleted afterwards.

**Runtime validator**: four new cases in `test/config/client_config_schema_test.dart`
(missing, malformed with spaces/punctuation, leading separator, non-string), all
rejecting with the exact path `"tenantId"`.

**Green runs**

```text
flutter test (5 affected files)        All tests passed, exit 0
[ e ] whitelabel-dry-run              PASS   1.3s   (real halal_boyz config)
[ a ] dart-analyze                    PASS  54.2s   (receipt 20261108T174257Z)
```

Functionality of the fleet is unchanged: nothing reads `tenantId` yet. That is
deliberate — the card is schema-only.

## Localisation

No new user-visible string reached the UI: violations flow through the existing
`ConfigViolation` channel exactly like `app.bundleId` and `_meta.schemaVersion`,
which are also English literals surfaced on the existing validation screen. Both
`.arb` files are therefore untouched — adding a key would have created a
translation obligation for a string that is never rendered as a localised label.
