# P0-9 — Functions test scaffold (coverage floor) — DONE

Coverage is now measured on every `npm run test:coverage`, and the gate fails
when any source file falls below its floor or when a source file has no
registered floor at all.

## Decisions that shaped it

- **c8, not Node's built-in `--experimental-test-coverage`** (D-014): the built-in
  reporter gives one aggregate number and no per-file threshold, and the card's
  requirement is a floor "for new/touched files". c8 gives per-file numbers from
  the same `node --test` run, so no test runner is replaced.
- **A registry, not a global threshold** (D-015): repo-wide coverage is 60.14%
  because `src/index.ts` — the 2282-line legacy entrypoint monolith — sits at
  22.3%. A global 90% would have been red from minute one and tuned down within a
  week. Instead every file carries its own floor: legacy files are frozen at
  their measured value, **new files get 90% by default because they have no row
  with a lower number**, and `--raise` ratchets floors upward only.

## What was added

| File | Purpose |
|---|---|
| `core_app/functions/scripts/check_coverage_floor.mjs` | Enforces the registry against c8's `coverage-summary.json` |
| `core_app/functions/coverage-floors.json` | Per-file floors + total floor, with notes on every debt item |
| `core_app/functions/package.json` | `test:coverage`, `coverage:raise`; `c8` devDependency |
| `core_app/functions/.gitignore` | `coverage/` (generated) |
| `gate_config.json` | Gate (g) activated |

The checker has three failure modes, all loud: **below floor**, **unregistered
source file**, and **stale registry row** (registered file deleted). Exit 1 for
those, exit 2 if the summary or registry is missing — it can never pass silently.

## Evidence

**The completeness rule did real work immediately.** The first run failed on
three files nobody had mentioned:

```text
COVERAGE-FLOOR: FAIL (3)
  - src/migrations/v001__seed_branches.ts is NOT registered …
  - src/migrations/v002__seed_admin_user.ts is NOT registered …
  - src/migrations/v003__seed_settings_owner_info.ts is NOT registered …
```

These are one-shot admin scripts that no test imports. They are now registered at
floor 0 with a note saying why, and the receipt labels them
`[not imported by any test]` rather than letting 0% look like a measurement.

**Planted regression fails** — an untested export appended to `src/access.ts`
(floor 100%), then reverted:

```text
FAIL  91.76% /    100%  src/access.ts
FAIL  60.07% /  60.14%  TOTAL
COVERAGE-FLOOR: FAIL (5)
PLANT_EXIT=1
```

**Clean run passes**, 13 files:

```text
ok    22.30% /   22.3%  src/index.ts
ok    60.14% /  60.14%  TOTAL
COVERAGE-FLOOR: PASS (13 files at or above floor)
[g] functions-coverage  PASS  8.2s   (receipt 20261109T124640Z)
```

**No behaviour changed**: `npm test` still runs `tsc && node --test` and still
reports 172/172; `src/` is byte-identical to before this card (`git diff --stat
src/` empty after the plant was reverted). The card authorises
`package.json` + test wiring only, and that is all that changed.

## Known debt, recorded rather than hidden

`src/index.ts` at 22.3% is the largest untested surface in the backend. The floor
freezes it so P1 cannot make it worse; raising it requires extracting handlers
into testable units, which is a P1+ task and explicitly out of P0 scope.
