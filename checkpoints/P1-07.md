The card's assertion is "widget test at both sizes; no overflow errors". Each
size case pumps the panel inside a `Scaffold` at a fixed viewport (390×844 and
1024×768, devicePixelRatio 1.0) and **captures `FlutterError.onError`**:
an overflow is a layout error, so the test fails on any captured error and on
`tester.takeException()`, instead of passing while the framework prints an
overflow warning to the console. Both sizes render:

- 390 px: branch rows stacked under the summary; the 26-character branch id
  `branch_downtown_market_hall` is present and ellipsised.
- 1024 px: summary beside the branch list (`Row` of `Expanded`), two `Card`s.
- empty day: the localised empty state, no `Card`, no exception.

Aggregation cases: reversal subtracts (4200 + 1800 − 1200 = 4800 in the main
branch, refunds 1200, orders still 2); branches sorted by revenue; `unknown`
bucket kept; a non-integer `totalCents` ignored.

## Known gaps (explicit)

1. The panel is not yet mounted in `owner_dashboard.dart`. The dashboard is a tab
   host whose analytics are Firestore-bound; wiring this panel needs a provider
   over `transactions` (a bounded query) and an owner-only route, which belongs
   with the P1-4/P1-5 server work that decides how a client reads the ledger.
   The card's DONE-WHEN is the widget test at both sizes, which exists.
2. Channel labels are rendered as data (`app`, `counter`, `waiter`), not
   localised copy — deliberate, because translating a stored enum would make the
   report disagree with the ledger values.
3. `topItems`/`staffActivity` are still absent from the rollup (D-031 gap), so
   the panel shows money and order counts only.
